## Interpretation and limits

This completes C1 because the real receipt supplements the already passing
native invariant negatives, journal/effects equality, and transparent-oracle and
Halo2 differentials. It does not activate a verifier, make the system safe for
real funds, C6, or A5.

C4 is complete. The receipt and provenance files are published in
[`c4-risc0-transfer-v2-v1`](https://github.com/TOMASCORZO/vault/releases/tag/c4-risc0-transfer-v2-v1)
with canonical public inputs, negative mutations, exact proof-size bounds, and a
portable offline-verification package. On the macOS M1 the package accepted the
receipt and rejected public-input, proof-byte, and truncation mutations in 74.57
seconds. The 311,977,650-byte receipt exceeds Vault's current 2,097,152-byte
consensus proof limit, so it remains non-activatable despite completing C4.

RISC Zero 3.0.6 includes absolute Rust source paths in guest panic metadata.
Therefore the reviewed image ID above is tied to the canonical
`/workspace/vault` build root even though the source and lockfiles were
unchanged. Offline verification must use the reviewed digest rather than
silently substituting a guest rebuilt at another checkout path.
